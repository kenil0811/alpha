# F02 — Real builder and model route

Status: in_progress. Owner: coding agent (self-review). Code from commit `d16c41c` onward.

## Route decision

The founder declined a provider API key and instructed the builder to use their Claude
subscription through the Claude Code CLI (docs/development/decisions/2026-09-25-builder-route-
claude-subscription.md). OpenCode is therefore not the first candidate for this engagement; the
CLI adapter implements the same BuilderHarness seam. This is an internal development route on
the founder's Mac, not a distributable entitlement.

## What was built

- Contracts: `BuildRequest`, `BuildResult`, `BuildEvent`, build states, `BuildBudget` with an
  explicit cost basis (provider_reported / subscription_unmetered / unavailable).
- `alpha.models.gateway.ModelGateway`: route registry (`fake`, `claude-code-cli`), enabled only
  through `ALPHA_ENABLED_MODEL_ROUTES` (default `fake`), budget policy from the plan's defaults
  (12 min per attempt, 30 min total, repair 0 until F07), usage rows in `model_usage`.
- `alpha.builds.service.BuildService`: build → attempt → workspace lease under
  `<data>/builds/<build>/attempt-N`; launches the `builder` worker profile with the harness;
  deadline timer outside the harness; cancel terminates the whole process group; startup
  reconciliation marks running attempts interrupted, kills orphaned trees and never revives a
  build; validation runs only after the harness claims a candidate: package present, layout
  (no symlinks, escapes, binaries, bytecode, size caps), manifest (contract 0.2, pure profile,
  no authority fields), real handler binding and execution in the disposable
  `candidate_runner` worker against acceptance examples whose expected outputs come from the
  brief, never from the candidate; package sealed with per-file digests
  (`package.index.json`) and a validation report; `invoke` re-verifies the digest before running.
- Harnesses: `FakeHarness` (control modes succeed/fail/hang/broken_package/claims_success) and
  `ClaudeCliHarness` (`claude -p --output-format stream-json --restricted --permission-mode
  acceptEdits --permission-prompts none --setting-sources "" --strict-mcp-config
  --no-session-persistence --tools Read,Write,Edit,Glob,Grep,Bash` with a Bash allowlist limited
  to the platform interpreter's py_compile/-c/unittest plus ls/cat, `--max-turns`, optional
  `--max-budget-usd`). Events normalized from stream-json; the CLI's final prose never decides.
- Workers run with `-I -B` (no ambient imports, no bytecode in sealed packages).
- API: `POST/GET /api/builds`, events, cancel, invoke, `GET /api/model-routes`.
- `just qualify-builder` (opt-in live run) and `just verify-ticket F02`.

## Findings during qualification

- A private `CLAUDE_CONFIG_DIR` cannot authenticate (login is bound to the default config home,
  even with the account record copied). Chosen: default home with all setting sources ignored.
- The CLI reports "Not logged in" unless `USER` is present in the environment; the builder
  profile now derives `USER`/`LOGNAME` from the process owner.
- The `claude` launcher is a standalone binary; PATH needs only `/opt/homebrew/bin`.

## Limitations

- No scoped gateway credential can be injected into the CLI route; controls are the restricted
  mode, prompt denial, tool allowlist and workspace cwd. OS containment is F03/F20.
- Cost on this route is a provider-equivalent estimate reported by the CLI, not a charge.
- The builder profile receives the founder's HOME (required for the login); F20 must qualify
  what a hostile candidate could read from it under the sandbox profile.
