# F07 — Candidate verification and bounded repair

Status: complete. Owner: coding agent (self-review). Depends on F02, F05, F06 (complete).

## What was built

- **One package path** (`services/core/alpha/data/packages.py`). Builder candidates and
  development fixtures are sealed by the same code:
  - the App contract and file rules; dependency, environment and platform files are refused by
    name;
  - exact runtime, SDK and UI profiles, re-verified on disk;
  - the UI compiled by the trusted build tool;
  - profile locks copied into `dependencies/` as provenance;
  - `dependency.manifest.json` and `package.index.json`, content-addressed and sealed read-only.

  The F02 package format and the candidate runner on Core's interpreter are gone.
- **Verification pipeline** (`builds/verify.py`), in stages, each producing named checks:
  - package, dependencies, seal;
  - handlers: every import scanned and every handler bound on the exact profile;
  - behaviour: independent scenarios run in fresh isolated previews (`builds/preview.py`), with
    persistence judged by reading storage;
  - UI: the sealed screen driven in a pinned headless browser (`workers/validator`);
  - the candidate's own tests, as supplementary evidence only.

  The `VerificationReport` contract derives its verdict. A skipped required check blocks
  readiness, and a report cannot claim otherwise.
- **Render check** (`workers/validator/src/ui_check.mjs`, Playwright 1.62.0). Each screen goes
  through these states, with screenshots retained:
  - **Empty:** a title, no error, no script errors, no sideways scrolling at 768px.
  - **Primary interaction:** addressed by visible labels; it must invoke a declared action, and
    the record must be stored.
  - **Populated:** sample data comes from the App's own actions.
  - **Failed read:** an error must be shown, not an empty screen.
  - **Failed save:** an error is shown, nothing is stored, and the input is kept (advisory).
- **Bounded repair** (`builds/service.py`, `builds/workspace.py`). Failed checks become
  REPAIR.md, with evidence and screenshots, in a fresh workspace seeded with the previous
  package. Limits are enforced outside the model:
  - at most two repairs;
  - 12 minutes per attempt and 30 in total;
  - the cost limit, where the route is metered.

  Every attempt, report and workspace is retained. A harness that reports failure stays failed.
- **Activation and invocation agree with validation.** `POST /api/builds/{id}/activate` installs
  the exact sealed bytes after rechecking them and the profile manifests. An App run refuses a
  Version whose profile manifest differs from the installed one. `/api/builds/{id}/invoke` runs
  a candidate in its preview, never on the person's data.
- **Dependencies outside the profile** become durable qualification requests
  (`/api/dependency-requests`). Platform internals, installers and computed dynamic imports are
  refused. A profile whose worker cannot scan imports fails verification rather than skipping it.
- **Builder context**:
  - the App template with profile markers;
  - `templates/app/APP_CONTRACT.md` and `packages/app-sdk/REFERENCE.md`;
  - the kit reference from the UI profile;
  - PLAN.md, and REPAIR.md on a repair.

  The CLI builder's shell allowlist is now compile and unit-test only.
- **Structure.** The F02 build service (1,190 lines) is split into eight modules: service,
  attempt, workspace, verify, preview, plan, ui_check and toolchain. Handler binding is its own
  class, which removes the startup placeholder cycle.

Decisions: docs/development/decisions/2026-09-26-f07-candidate-verification.md.

## Found by the live qualification (all fixed)

- **Section taken for a field.** The render check took a section titled "Write a note" for the
  field labelled "Note". It now matches form controls by role.
- **Screens are type-checked.** A generated table without its required `caption` crashed the
  screen at run time, and the builder guessed the wrong cause. The trusted UI build now
  type-checks screens with TypeScript 7.0.2, strict, against the kit's types, so a mistake fails
  the build with its line.
- **The builder's shell reached outside the workspace.** Its `ls`, `cat` and `python -c` could reach
  any path. The allowlist is now compile and unit-test commands only.
- **Two error checks were demanded where they cannot apply.** The failed-read check is skipped for
  a screen that reads nothing, and the failed-save check for an interaction the plan does not
  require to save.

## Scope boundary kept

Candidate-authored tests are supplementary and never gate readiness. Independent expectations
come from the plan written before the build; the builder sees a copy it cannot change. No
source-specific branch in Core. Activation is the minimal install of a verified candidate; the
user-facing delivery loop, release history and expected-current-release checks are F08/F10.
