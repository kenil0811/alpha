# F05 — Record/artifact/model SDK

Status: in_progress. Owner: coding agent (self-review). Depends on F01, F02, F04 (complete).

## What was built

- **Contracts** (`packages/contracts`): `apps` (the `app.yaml` source contract, package index),
  `records` (field specs for text, number, integer, boolean, date, datetime, choice, reference and
  bounded JSON; collection schemas with indexes and unique constraints; typed filter AST, sort,
  query, aggregation; create/update/correct/delete/batch; per-field provenance), `artifacts`,
  `profiles` (DependencyProfile and per-Version DependencyManifest with the §11 canonical digest
  and derived IDs) and `broker` (worker call/reply shapes, structured model call). The execution
  snapshot now pins Version, package digest, runtime profile and dependency manifest.
- **SDK** (`packages/app-sdk`, `alpha_sdk`, standard library only): `ctx.records` (get, create,
  update, correct, delete, query, all, aggregate, batch), `ctx.artifacts` (create, get, read),
  `ctx.models.structured` (bounded output declared with field specs, result labelled an
  estimate), `ctx.today()/now()/log()`, typed errors and query builders
  (`eq, gte, contains, one_of, all_of, any_of, not_, count, total, average, by_day, …`).
- **App worker** (`workers/app`, `alpha_app_worker`): validate mode (imports each handler,
  checks its signature against the input schema) and invoke mode (runs one handler with a
  Context). The original stdout is the protocol stream; handler output goes to stderr.
- **Default runtime profile** (`tools/build_app_profile.py`, run by `just bundle-core`): builds
  reproducible wheels, writes a hash-pinned lock, installs into staging with uv on the pinned
  CPython, validates, seals read-only and publishes atomically as `pyprof-<id>`; idempotent.
- **Core**: `ProfileInventory` (verify and register published profiles; ready or quarantined),
  per-App record stores (`alpha/data`: SQLite per App, compare-and-swap writes, idempotency keys,
  unique keys, reference checks, one-transaction batches, typed query compiler with page/group
  limits, timezone-aware day/week/month buckets), `ArtifactService` (staged, fsynced,
  content-addressed, read-only blobs; digest re-verified on read; owner-scoped; restart
  reconciliation), `AppModelService` (per-run call budget, input size limit, output validated
  against the declared specs, calls and usage recorded, provenance only from the same run),
  `CapabilityBroker` (per-run workload tokens bound to the run's pipe, declared-capability check,
  owner from the run, typed failures), `AppRegistry` (validate `app.yaml`, collect safe files,
  seal a content-addressed Version with `package.index.json` and `dependency.manifest.json`,
  resolve handlers in a disposable worker on the exact profile, register collections and the
  minimal release pointer) and `AppRunService` (input schema check before a Run exists,
  invocable-from check, exact-profile worker, output schema check before success).
- **API** (trusted shell): `/api/runtime-profiles`, `/api/apps`, `/api/apps/{id}`,
  `/api/apps/{id}/actions/{action}/runs`, `/api/apps/{id}/records/query|aggregate`,
  `/api/apps/{id}/artifacts`, `/api/artifacts/{id}` and `/content`, `/api/runs/{id}/model-calls`,
  and the development-only `/api/dev/fixture-apps/{name}/install`.
- **Fixtures** (`tests/fixtures/apps`): two neutral Apps (an item list and a tally) used by the
  integration tests; no exemplar-domain logic.

Decisions: docs/development/decisions/2026-09-25-f05-worker-channel-and-default-profile.md.

## Scope boundary kept

No job/calorie tables or rules; generated code has no SQL, database path, credential, port or
route. F09 concurrency proof is not claimed: the stores use one serialized connection per App and
offset cursors. The coordinator change is shared with F01 runs, whose tests still pass.
