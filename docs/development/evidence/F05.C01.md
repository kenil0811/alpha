## Expected
Generated-style handler code, running in a real App worker process and using only `ctx.records`, can create, read, update, delete, filter, sort, paginate, project and aggregate records whose values are validated and normalized by Core, and the same records are there, unchanged, after Core restarts.

## Observed (tests/integration/test_app_records.py, 2 tests)
- Four items created through the `add_item` action. A datetime given as `2026-09-25T04:00:00+05:30` was stored as `2026-09-24T22:30:00.000000Z`; bounded JSON tags round-tripped.
- Update at revision 1 → revision 2; clearing an optional field (`price: null`) removed it.
- Filters: category equality with descending quantity sort gave `[paper, pens]`; `quantity >= 5` gave two records; case-insensitive "PE" substring gave `[paper, pens]`; projection returned only `title`.
- Pagination: `limit 2` sorted by title gave `[apples, paper]` with a cursor, then `[pens, soap]` with no cursor.
- Aggregation: by category, home {n 2, quantity 4, avg_price 2.25}, work {n 2, quantity 19, avg_price 2.5}. By day of `happened_at` in Asia/Kolkata: 2026-09-24 → 1, 2026-09-25 → 2, 2026-09-26 → 1; the record at 20:00Z on the 25th falls on the 26th locally. Overall: n 4, latest `noted_on` 2026-09-23, quantity 23.
- A batch of two creates committed together; a note referencing an item was accepted; the same idempotency key and values returned the same record id twice; delete at the current revision removed the record. The trusted shell's query route returned exactly the six expected titles.
- Restart: the full record set read through the shell before stopping Core equalled the set read by a new Core instance (`identical_after_restart: true`, 4 records). A fresh worker in the new Core read revision 2, updated to revision 3 and aggregated the new total (22).

## Limitations
Single writer at a time per App store (one serialized SQLite connection); concurrent multiwriter behavior and idempotency under races are F09. Offset cursors can shift under concurrent writes (decision 2026-09-25-f05, item 6). Records are App-owned only; Task-scoped records arrive with F11.
