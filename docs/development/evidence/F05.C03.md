## Expected
Artifact bytes, size and SHA-256 are exactly what the App produced. Metadata carries owner and run/action/Version provenance with a logical storage reference and no paths. Model output is bounded by declared field specs, labelled an estimate with provenance, and a person's correction replaces it while keeping the estimate as history.

## Observed — artifacts (tests/integration/test_app_artifacts_models.py)
- A CSV built in the worker (78 bytes, with quoting of commas and quotes) had worker-side SHA-256 `3867c3e9…90e9`. That equalled the registered digest, the `X-Content-SHA256` header, the digest of the bytes served by the shell route, the digest the worker computed on read-back, and the content-addressed blob name. The blob is read-only.
- Metadata: owner `{app, items-fixture}`, media type text/csv, storage_ref `blob:sha256:3867c3e9…`. Provenance: created_by app_run, run id, action `make_report`, version `ver_b2615bfac3c163cda52d4693`, package digest `b2615bfa…61b0`. The data directory path does not appear anywhere in the metadata.
- A disallowed media type → invalid_input; 10 MiB + 1 byte → limit_exceeded. After a restart, an abandoned staging file and an unregistered blob were removed, and the registered artifact still read back with the same digest.

## Observed — model estimates
- Fake route: `estimate_quantity` returned 50, the midpoint of the declared 0–100 integer bound. The record's `quantity` provenance is `model_estimate` with the call id and route; typed fields carry no model provenance. The model-call row is status ok with output `{"quantity": 50}`, and usage is recorded as `(fake, app_run)`.
- Correction from a UI-started run: value 12, provenance `user_correction` with previous `{value 50, source model_estimate, call_id …}`, revision +1, and `is_estimate` false. The same correction from a trigger-started run failed as forbidden.
- Bounds: citing another run's model call as provenance → forbidden. The fake route's out-of-bounds output (11 for a 0–10 field) → unavailable with "outside the requested bounds; nothing was stored", and the call row is `rejected`. A 12th call in one run → limit_exceeded (budget 10).
- Live route (supplementary): the same action on `claude-code-cli` succeeded twice, in 2.6 s and 4.6 s end to end (the recorded file is the second run, made with the committed tool). The model returned `{"quantity": 8}` for "AA batteries" both times, through the JSON Schema generated from the field spec. Provenance names route claude-code-cli and model claude-opus-5[1m]. Usage was recorded as `(claude-code-cli, app_run, subscription_unmetered)`, 4,359 ms in the recorded run. A UI-run correction to 4 kept the estimate as the previous value.

## Limitations
The integration check uses the deterministic control route; the live smoke is one call and not a quality evaluation of estimates. Exports to a user-selected destination through the host are F11. Artifacts are App-owned only; Task-owned artifacts arrive with F11.
