- Check: F03.C01 (evidence kind: native)
- Code: working tree at commit 2b5c1238f89a328aa2c20f541af2772e1f2f31a6 plus the uncommitted fixture/host changes committed immediately after this run (same content); app bundle built with `pnpm tauri build --debug --bundles app` and launched from its binary.
- Environment: macOS 26.6.2 (25G83) arm64; Tauri 2.11.6 debug .app (WKWebView); CPython 3.13.9 runtime; Node 24.21.0 for builds
- Protocol: the shell's "Isolation fixture" panel mounts two frames of arbitrary React (apps/desktop/fixtures/generated-ui) served from their own origin `alpha-ui://fixture_a/` and `alpha-ui://fixture_b/` with `sandbox="allow-scripts"` (opaque origin) and a strict per-document CSP header. Driven through the desktop control tool (real clicks in the real WebView); frame output read from the rendered frames; Core state read from control.sqlite.
- Reviewer: self-review (coding agent)

## Observed in frame A (session sess_apikegymgm, actions ["synthetic.echo"], views [])
- Isolation probes executed by the frame's own script: **16/16 pass** — `__TAURI_INTERNALS__` and `__TAURI__` undefined; `parent.document` and `parent.__TAURI_INTERNALS__` throw; `fetch` to `ipc://localhost/…`, `http://ipc.localhost/…`, `http://127.0.0.1:<core port>/api/health` and `https://example.com/` all rejected; WebSocket to loopback throws; localStorage throws; `window.open` returns null; `top.location` navigation blocked; `form.submit()` does not navigate; dynamic import from the network rejected; `document.cookie` empty; `window.origin` is "null".
- Bridge: `action.invoke synthetic.echo` → ok, operation run_faf12268c44447ac8985eada4f996b3c; Core shows that run created by the shell (state succeeded, output "HELLO FROM GENERATED UI") — the frame never held the shell credential or the Core port. `operation.observe` of its own operation → ok. `operation.observe` of an id it did not create → forbidden "operation is not owned by this session". `records.query` → forbidden (no granted view). `shell.navigate` → unsupported (no handler here).

## Observed in frame B (session sess_l52imupi76, actions [], views [])
- `action.invoke synthetic.echo` → forbidden "action synthetic.echo is not granted to this session"; no run was created (control store newest run remained A's; run count unchanged).
- Shell "Revoke" → frame shows "REVOKED: revoked by shell"; its next `action.invoke` → "revoked: session revoked". Shell "Reload frame" → the frame reloaded and negotiated a new session (sess_xu8xtzwy3i) with the same empty grant; the old port is closed.
- Session A and B ids differ; each frame holds exactly one transferred port; the host attaches a port only to the frame window that sent `bridge.hello` (compared by window identity, not origin string).

## Findings recorded
- `srcdoc` frames inherit the shell CSP (the first build rendered blank frames); own-origin serving via a custom protocol is required and implemented.
- Text entry into the sandboxed frame through the automation tool did not land, so the foreign-id observe in frame B used the fixture's fixed not-owned id (same host check) rather than A's real id; the real-id case is covered by packages/ui-bridge/src/bridge.test.ts over real ports.

## Limitations
Feasibility on nonsensitive fixtures; F20 owns adversarial qualification. WKWebView only (Windows form of custom-scheme URLs differs).
