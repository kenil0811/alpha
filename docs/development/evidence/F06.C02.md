# F06.C02 — Supported widths, long labels, empty states and accessible names/focus have no blocking defects

- Check: F06.C02 (evidence kind: rendered_ui)
- Code: commit d949198 (kit sources identical to the published profile uiprof-fe345cfb0d6818ad55a1)
- Environment: macOS 26.6.2 (25G83) arm64; Node 24.21.0, pnpm 10.34.5; React 19.3.0 and Vite 8.3.1 from the UI build profile; Chromium (Claude desktop app built-in browser pane) at 768/1024/1440 CSS px in light and dark schemes; development Core (CPython 3.13.9, SQLite) with the neutral entries fixture App on runtime profile pyprof-48e953297d79b3ac3547; axe-core 4.13.0
- Protocol: the kit reference sheet shows every pattern with neutral data. In a real browser, each of 768, 1024 and 1440 px in light and dark was swept through populated, empty, loading and failing states, with and without long labels. Each case measured overflow, sideways scrolling and axe-core over the whole document with all rules, colour contrast included (48 cases). The compositions were checked visually at 768 and 1440 px in the kit fixture. Automated tests add axe in jsdom for every component state and a token contrast test.
- Logs: docs/development/evidence/logs/F06-reference-sweep.md; `just test-ui` in docs/development/evidence/logs/F06-verify-ticket-d59e85d.log
- Reviewer: self-review (coding agent)

## Observed
- 48 of 48 sweep cases: 0 axe violations, 0 elements past the viewport, no sideways scroll. The state markers confirm each state rendered: populated 20 table rows; empty shows "Nothing here yet"; loading shows skeletons and "Loading the trend…"; failing shows "Items could not be loaded" with a retry.
- Long labels (page, section, field, column headings, table titles, checkbox) wrap at every width. Below 640 px the table becomes labelled cards; at 768 px composition A's filter bar wraps to two rows and its table fits the 655 px frame.
- Accessible names and roles: every control has a visible label; sort headings expose `aria-sort`; row open buttons read "<title>, open details"; selection checkboxes read "Select <title>". The drawer is a labelled modal dialog. Status messages carry a text prefix ("Done:", "Problem:") and an icon, never colour alone. The trend exposes a summary label and a data table in which missing days read "No entry".
- Focus: a 2 px outline on every focusable element was visible in the rendered screenshots (search, select, row button, drawer Close, Amount, review card, Undo). The drawer returned focus to the row that opened it. Quick entry kept focus in its input after save, failure and undo.
- Automated: `tokens.test.ts` gives 38 contrast assertions, all passing: text pairs ≥ 4.5:1 and borders, focus and chart marks ≥ 3:1 in both themes. `Accessibility.test.tsx` runs axe in jsdom with colour contrast excluded over populated, empty, loading and failed states with long labels and over the open drawer: 0 violations. A guard test proves axe flags an unlabeled input in this setup.

## Findings recorded
- **Defect, fixed:** at 768 px with long labels the page scrolled sideways (36 elements overflowed; the table was 938 px wide) because table headings could not wrap. Headings and sort buttons now wrap; re-measured 0.
- **Defect, fixed:** while trend data loaded, the chart showed every day as "no entry". It now shows a loading state.

## Limitations
Chromium only; WKWebView behaviour of the same markup is expected to match but was not captured natively here. The compositions' own documents could not be scanned by axe from outside their opaque-origin frames, so they are covered by the kit sweep plus visual review. This is not a user study (F23).
