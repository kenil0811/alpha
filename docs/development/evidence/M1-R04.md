## F03: an App without its own screen is one clear form with a readable result

**Contract.** An App's `primary_action` (0.2, optional) names the one action a person runs to
get the result. It must be declared and runnable by hand (contract tests). For an App without
its own screen, verification requires it (`package.primary_action`), so a screenless candidate
without one is not made ready (integration test). The App template, the notes fixture and the
fake builder's package declare it.

**Inputs.** The shell honours the App's `multiline: true` hint, or a description asking for one
entry per line, and shows a multi-line box. A list of texts is a one-per-line box. The old
field-name guess remains only as a last resort for older Apps.

**Actions view.** The main action leads, highlighted. Other simple actions sit under "More
actions". An action that needs structured input, such as another step's output, is never
offered as a form; the view says "One more step runs inside this workflow and needs no input
from you."

**Results.**
- Lists of entries become tables, lists of words become lists, and groups become nested
  details.
- Yes/No and numbers are formatted; ids and revisions are not shown.
- **No raw JSON is ever shown.**
- A file result says it can't be opened from Alpha yet.

**Guidance.**
- The App contract, the builder's no-screen instructions and the assistant rules say:
  - set `primary_action` and keep helper steps internal;
  - mark long text `multiline`;
  - return readable data;
  - "Nothing runs inside this conversation". The G1 held-out reply had promised to "get the plan
    back in the conversation", which does not exist.

**Tests on a real generated manifest.** The G1 held-out planner's `app.yaml` actions and a real
`fit_plan` result were converted unchanged into `apps/desktop/src/test/fixtures/dayplan-app.json`.
`noScreen.test.tsx` checks:
- the List field is a multi-line box;
- pasting the six-line list and entering 4 hours runs `fit_plan` once with exactly that input;
- the result shows the plan and the won't-fit items as tables, and "Minutes spare 25";
- **no `{ } [ ] "` appear anywhere in the result**;
- the helper `read_list` sits under More actions, and `report_plan`, which needs structured
  input, is not a form;
- without a declared main action, no structured-input form is offered either.

**Both tests fail on the pre-repair actions view.**

## F07: no silent second App

After a creation is active, the Assistant no longer shows "Change or add something". It says:
"Changing Notes list after it was made isn't possible yet; that arrives in a later release. You
can describe a separate workflow instead; this one and its data stay as they are." A **Create a
separate workflow** button starts a new request with the original text filled in.

While a creation is running, corrections wait: "You can change the request once this attempt
finishes, or after you stop it." Before anything is made, corrections still revise the brief.
Tests in `continuity.test.tsx`. The data-preserving change flow stays in F10, as the review
directs.

## F12: file delivery is not promised

The capability catalog now marks `artifacts` unavailable: "Alpha can keep files a solution
makes, but you can't open or save them from Alpha yet" (arrives with F11). The F05 artifact APIs
are unchanged. The assistant therefore names the limit before offering a file result. The shell
example that implied one ("Turn my meeting notes into a one-page brief") is replaced with a
supported one. A file result in the actions view says it can't be opened from Alpha yet.
