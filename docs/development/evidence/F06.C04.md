## Observed
- **Same kit for every build.** The test builds a fresh profile, then both compositions and the App template against it. All three `build.json` reports name that profile, the kit tarball `alpha-ui-kit-0.1.0.tgz` and the same installed-tree digests as the profile manifest. Every bundled kit module resolved inside the profile's `node_modules`. `unpinned` is empty. The only App modules are each composition's `main.tsx`, plus the platform-written `index.html`.
- **The shell's copies came from the same profile.** Review: 12 kit modules, 1 bridge module, React/react-dom/scheduler, output `72785899da1c…`, 262,652 bytes. Entry: the same module set, output `99a5a6178d95…`, 261,836 bytes.
- **No vendored forks.** Composition and template sources contain no kit implementation, checked against kit component and bridge signatures. They import only `react`, `react-dom/client`, `@alpha/ui-kit` and its stylesheet.
- **Refused builds.** A source importing the workspace kit by path failed with "modules resolved outside the App source and the profile". A source with a remote import (`https://…`) failed as well.
- **One static document.** Each output is `index.html`, `index.csp` and `build.json` only. The script is inline and hash-pinned, there is no `<script src>` and exactly one `</script>`. The CSP includes `default-src 'none'`, `connect-src 'none'`, `form-action 'none'`, `base-uri 'none'` and `font-src 'none'`. Two builds of the same source are byte-identical.
- **No App server.** Nothing is served per App; the rendered check ran the documents in sandboxed frames (F06.C01).
- **Core verification.** Core registers the UI profile as `ui_build`, `ready`. A copy with one installed file changed is `quarantined`: "installed files differ from the sealed installation record".
