## Cancel (docs/development/evidence/logs/F02-live-cancel-20260925T161805Z/record.json)
- Tree before cancel: builder worker pid 82923 and `claude -p` pid 82925 (its descendants included by walk).
- `POST /api/builds/{id}/cancel` → 200. Four seconds later no pid of the tree was alive; build state cancelled, terminal_reason cancelled_by_user, attempt status cancelled; last events builder.result → builder.exited → build.cancelled. The builder worker honoured SIGTERM (harness.cancel) and the supervisor terminated the process group.

## Core killed mid-build, then restart (docs/development/evidence/logs/F02-live-restart-20260925T161914Z/record.json)
- Tree before: builder worker 82992 and `claude` 82994. Core SIGKILLed while the CLI was in tool use: both pids still alive one second later (orphaned, as expected for an uncontrolled Core death).
- Core restarted on the same data directory: startup reconciliation terminated the orphaned group; tree alive after restart: none; build state failed, terminal_reason core_restarted_builder_orphaned, attempt status interrupted; attempts count stayed 1 (no automatic re-run); last event build.interrupted.
- The same behaviour holds when the host disappears: Core's parent-watch (F01) stops workers before exiting, and a stale attempt found at startup is never resumed.

## Limitations
The shell has no build surface until F04/F08; cancellation and restart were driven through Core's authenticated API on this Mac rather than through a button. Descendant capture relies on the process table at the moment before acting; the CLI's short-lived subprocesses that had already exited are not listed.
