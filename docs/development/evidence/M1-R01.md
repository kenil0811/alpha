## What changed

| Finding | Repair |
|---|---|
| F01: the shell squeezed each page into the first of two columns | One working column. Assistant, My workflows and Activity are reading surfaces centred at up to 880 px; the workspace uses the full width. The App's own screen takes the height left in the window and is the only thing that scrolls. Two- and three-column grids remain only for the development fixtures. |
| F02: navigation lost the conversation | The selected conversation lives outside the Assistant panel and is remembered per window. **Recent requests** lists earlier requests with where each got to. **My workflows → Being made** leads back to in-progress work. |
| F06: one failed status request stalled progress | Polling continues through failures with backoff, shows "Lost contact … reconnecting", and offers "Check now". |
| F06: a failed turn had no next step | The failed-turn card offers **Try again** (new `POST /api/conversations/{id}/retry`, which reruns the same input without adding a turn) and **Start over** (puts the original request back in the box). |
| Found while repairing | A turn cut off by a restart stayed `thinking` forever. Core now marks it failed in plain words at startup. Turn failures are worded for people, e.g. "the model service took too long to answer" instead of "InferenceError: …", with the cause kept in the log. |

## Automated evidence

- `apps/desktop/src/workflows/continuity.test.tsx` (6 tests):
  - a request and its creation survive visiting every surface and coming back;
  - they are restored when the window opens again;
  - Recent requests reopens an earlier request;
  - a failed status request is followed by recovery;
  - Try again and Start over keep the request;
  - Start over is offered when retry isn't possible.

  **All six fail on the pre-repair shell** (files swapped back from `c8fd065`) and pass on the
  repair.
- `tests/ui/test_shell.py` builds the **production shell** against a real Core and runs it in the
  pinned headless browser. It measures each surface at 1100 and 768 px, and follows a request
  through navigation and a reload. Results:
  - at 1100 px, Assistant and My workflows are 880 px centred in a 1052 px area, and Activity is
    1052 px;
  - at 768 px, every surface is 720 px wide;
  - nothing scrolls sideways, and the request is still shown after navigation and after reload.

  **With the old two-column CSS restored, the test fails at a 411 px surface**, the review's
  estimate.
- `tests/integration/test_assistant.py::test_a_turn_cut_off_by_a_restart_is_reported_and_can_be_retried`:
  a thinking turn becomes failed with "Alpha was closed or restarted while it was thinking about
  this". Retry reruns it to `briefed` without a new user turn, and a second retry is refused
  with 409.
- Suites at `ce6c30a`: UI 42 tests, integration 135 tests, `just check` and mypy all pass.

**Found in the native session, and fixed in the follow-up commit**
- **Double scrolling.** The App's screen was a little taller than the room left, so the page
  scrolled as well as the screen. The screen now takes the remaining height.
- **Wrong message.** A runtime problem was shown as "The screen asked for something it is not
  allowed to do". The shell now speaks only about blocked requests ("Alpha blocked a request…")
  and Apps that can't run ("…its runtime on this Mac needs attention"). Ordinary failures are
  left to the App's screen (unit test added).
- **Activity wording.** It showed App runs as "0 words · 0 characters", the development
  fixture's format. It now reads "Daily Food Log · Log entry", with times, and ids moved under
  Details.
- **Technical ids on screen.** The workspace showed ids (`ver_…`, `pyprof-…`); they moved to a
  tooltip. The runtime status shows "Runtime connected", with versions in a tooltip. Navigation
  and the back button no longer wrap at 768 px.
