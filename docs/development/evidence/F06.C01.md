## Findings recorded
- **Real defect, fixed:** sandboxed frames without `allow-forms` never fire `submit`, so the first build's Save and quick-entry Enter did nothing and no action reached the bridge. The kit's `Form` now performs submission itself. A test swallows every submit event to reproduce the sandbox. The bridge contract keeps forms denied.
- **Copy defects, fixed after the walkthrough:** the failure sentence lacked a full stop ("1000 Your text"), and "1 entries". `friendlyError` now ends messages with punctuation and the count pluralises. Re-rendered at 768 px showing "2 entries".
- Composition B saw composition A's correction only after its own next refresh: separate sessions do not push updates to each other. Recorded for F08.
- Tool limits, not product behaviour: the browser tool's text-typing action re-targets the last clicked element, its Return reaches buttons but not a browser's implicit submit, and very fast repeated keys were sometimes dropped. The walkthrough used single key presses with short waits.

## Limitations
Chromium in the browser pane, not the native WKWebView. Native serving of App UI from sealed Versions arrives with F08, and `srcdoc` in the shell inherits the shell CSP (decision 2026-09-25-f06, item 5). Frames used `srcdoc` on the development page because the pane refuses requests from sandboxed frames.
