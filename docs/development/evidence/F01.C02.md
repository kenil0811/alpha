# F01.C02 — Worker error and cancellation produce honest durable state; descendants terminate

- Check: F01.C02 (evidence kind: native)
- Code: commit `a6b1121443f1d3cbd3d6bca94f43fde404286eac`; same build and protocol as F01.C01
- Environment: macOS 26.6.2 (25G83) arm64 Apple Silicon; uv 0.12.17; CPython 3.13.9 (uv-managed); Node 24.21.0; pnpm 10.34.5; rustc 1.98.1; just 1.58.0; Tauri 2.11.6 debug .app bundle
- Reviewer: self-review (coding agent)

## Expected
A worker that reports an error yields a failed run with the reason; cancelling a hung worker from
the desktop terminates the worker and every descendant and records a cancelled run; nothing is
shown as successful that did not succeed.

## Observed (commit a6b1121)
- Failure: mode "Fail inside the worker" → card FAILED "Reason: the worker reported an error",
  10 events. SQLite: run_15152ca3…f85a failed, terminal_reason worker_error; run.failed payload
  {"error": {"code": "synthetic_fail", ...}, "exit_code": 3}. No worker processes remained.
- Timeout (no cancel issued): mode "Hang" run_bb6e64c5…074c reached the 60 s limit while the
  desktop was in use by the user → see the database row below for its recorded terminal state.
- Cancellation from the desktop on this build: PENDING (the user was using the Mac when the step
  was due; the Cancel click could not be performed). On the previous build (f448485+, identical
  coordinator/supervisor code) the desktop Cancel produced CANCELLED "Reason: you cancelled it",
  run.cancelled payload {"termination": {"sigterm_sent": true, "sigkill_sent": false,
  "worker_running": true}}, worker pid 78161 and child `/bin/sleep 600` pid 78162 gone within
  1 s, lease released.

## Attempts
1. A worker descendant inheriting stdout kept a finished run "running" in the first implementation;
   fixed by waiting on the leader and terminating the process group (1597ea1).
2. Explicit quit with a live worker orphaned it (uvicorn waited for the shell's SSE stream);
   fixed in a6b1121 by stopping workers before HTTP shutdown.
