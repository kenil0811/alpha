## Platform defects found by the native runs, and fixed

Each fix comes with tests that fail on the code before it.

1. **Plan coverage compared names.** The M1-R06 check matched the brief's display name ("Food
   entries") against the plan's storage name (`food_entries`), and refused a plan that did read
   its data back. Coverage is now judged per action: every write is followed by a read-back.
   Commit 45532a2.
2. **Planning failures were shown in developer words** ("the checks are incomplete: …"). The
   person now sees "Alpha couldn't work out how to check this request, so nothing was made."; the
   gaps sit under the card's details. Commit 45532a2.
3. **Records-step filters were not resolved.** `{"$today": 0}` reached the store as-is, so
   every read of the collection failed ("filter on date must be text"). The builder spent its
   repairs changing the date field's type back and forth. Commit a1388d5.
4. **Sample data was seeded on top of earlier entries.** The screen's interaction checks,
   including M1-R05's repeat entry, had already saved entries, so a sample-only day total of 840
   showed as 1,540. Core now empties the preview's collections before seeding. Commit a1388d5.
   - Re-verifying the builder's own third package from run 2 with fixes 3 and 4: **66 of 66**
     checks pass.
5. **An advisory skip blocked the screen checks.** When no planned step makes an action (here
   `edit_entry`) call the model, `model.failure.<action>` is an advisory skip. The screen stage
   treated it as failure, so no App with such an action could pass. Stages now gate on required
   checks only. Commit 5c9bd26.
6. **The planner didn't know the screen's check order.** It counted the sample data in the
   interaction's save (3 entries, total 650). The interaction actually runs on an App with
   nothing saved, and the samples come later, alone. The planner is now told the order, and a
   `ui.saved` count above 1 sends the plan back for its one rewrite. Commit 5c9bd26.
   - Re-verifying run 3's first package: ready, with those two expectations corrected.
7. **Smaller fixes:**
   - "It was built 3 time(s)" now reads in plain words (d9e209a).
   - `g1.py record` now names the frozen build, not the checkout's HEAD, and keeps failed
     creations (1a32e34).
   - Six shell tests raced the "Connecting to runtime" status (4cd7f35, tests only).
