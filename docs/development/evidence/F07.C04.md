## Limitations

- **Qualifying a new profile is not automated.** A qualification request records the exact
  package, version and location, and stops there; building and qualifying the new profile remains
  a trusted, manual path (Blueprint §10).
- **Isolation still depends on file permissions.** Read-only permissions and verification before
  use are not OS isolation. F20 must show that workers cannot write shared artifacts through any
  permitted path.
- **Profiles are re-verified only at key moments.** That happens at startup, validation and
  activation. An App run checks that its Version's manifest agrees with the registered profile,
  but does not rehash the installation on every run.
