# Local automation and extension profile

Baseline R2 · contract 0.2. Normative scheduling fields and DST behavior are in Current Release Specification section 9. Delivery requirements are F13–F18.

The functional alpha includes HTTP/file access, dedicated browser work, supported form assistance, runtime model calls, local recurrence and evidence-based repair. These capabilities serve both Task and App owners. Local recurring work needs a reusable App/trigger, but a one-off browser action does not.

Connection profiles contain account metadata and secure secret references. Login/takeover, expired access and unsupported forms are distinct recovery paths. UI and generated code cannot obtain cookie/storage files. Browser field filling may autosave and must follow the qualified effect profile. Submission outcome requires evidence; unknown outcomes cannot trigger blind retries.

Closing the main window preserves runtime operation; explicit quit stops it. Missed/overlapping occurrences remain visible and require deliberate manual retrigger. New profiles declare schemas, authority/effects, budgets, compatibility, failure/reconciliation and conformance tests. Sources, domains and models remain configuration, not hardcoded product use cases.

Public webhooks, desktop accessibility actions, cloud execution, audio generation and new authentication protocols require their own qualified extension work. Do not import old future-profile samples as shipped R2 capabilities.
