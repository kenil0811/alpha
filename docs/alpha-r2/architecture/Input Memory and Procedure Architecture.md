# Input, context and future memory

Baseline R2 · 24 September 2026. Owns context selection and extension boundaries.

The current release accepts text, deliberately selected files, links and scoped connected information. Keep the user's request, clarifications, brief revisions, source references/digests and corrections so change/repair does not start from zero. These records are operational context, not permission to read the whole device or a claim of broad personal memory.

A ContextSnapshot records selected input references, source/owner, observed time, content digest where available, classification, redactions and allowed purpose. Resolve it through platform adapters. The builder receives a bounded projection; generated work gets only the handles its grant permits. Treat web/file content as evidence, not instructions with authority over the user or platform.

Later memory adds explicit claims with provenance, confidence/confirmation, correction, exclusion, expiry and deletion. Cross-App retrieval is opt-in and independently scoped. Retaining a conversation does not automatically promote every statement into a durable personal fact or allow it to answer application forms.

Voice, screen capture and watch-and-learn are later input adapters. Capture must be deliberate and visibly active, with bounded retention. Observing a procedure can produce a suggested checklist/workflow; it does not authorize performing the observed actions. A future desktop provider must qualify its own authority and execution boundary.
